# conifer-stress-comparative-genomics

[![DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.21628206.svg)](https://doi.org/10.5281/zenodo.21628206)

Code for:

**Comparative genomics of abiotic stress response in Norway spruce and Scots pine**
van Zalen et al.

This repository contains only the analysis code. The data are archived separately (see
below). Combining the two regenerates every figure, table and reported number in the paper
via a single driver script, [`reproduce_paper.sh`](reproduce_paper.sh).

## Reproducing the analysis

**1. Clone this repository.**

**2. Download the data and extract it in place.** All inputs, and where to obtain each, are
listed in [`SOURCES.tsv`](SOURCES.tsv). In brief:

- This study's FigShare deposit (doi:10.17044/scilifelab.32593647) provides the expression
  matrices, DESeq2 objects and DE tables, the ComPlEx co-expression network output
  (`results/ComPlEx/`), the per-gene annotation (`data/annotation/gene_annotation.tsv.gz`),
  orthology tables, sample metadata, and the small curated study inputs the pipeline reads but does
  not regenerate (`curated_inputs.tar.gz` → `data/chs3/`, `doc/`). Download and extract the archives
  into the repository so they populate `data/` (the DESeq2 objects land in `data/dds/`, the
  annotations in `data/annotation/`), `doc/`, `Orthogroups/` and `results/ComPlEx/`. Every archive
  extracts at the repository root and carries its own internal paths — no per-file placement is needed.

  This repository is code only: pipeline outputs (`results/` and `manuscript/supplementary/*.xlsx`)
  are not stored here — they are regenerated by `reproduce_paper.sh` from the deposited inputs.
- The Kalman et al. deposit (doi:10.17044/scilifelab.28737623) provides the
  population-genomic and Hi-C inputs (`data/popgen/`, `data/epigenetics/`) and the genome
  CDS / protein / repeat / annotation files. Its `Orthogroups/` folder also provides
  `Phylogenetic_Hierarchical_Orthogroups_N0.tsv.gz` (the OrthoFinder root node, all 27 species
  including angiosperm/gymnosperm outgroups) — place it in `Orthogroups/`; it is needed for the
  no-1:1 novel-gain vs lost/diverged vs expanded classification (`no1to1_broad_species_class.R`).
- Rodriguez et al. (bioRxiv doi:10.1101/2025.06.28.661522) provide `data/wood/`.

**3. Place the genome files** (spruce Picab02 / pine Pinsy01 CDS, protein, repeat GFF and
TSS GFF; see `SOURCES.tsv`) under a directory of your choice and point `DATA_ROOT` at it
(default `./genome_data`).

**4. Run the pipeline:**

```bash
DATA_ROOT=/path/to/genome_files ./reproduce_paper.sh
```

`reproduce_paper.sh` runs every stage in dependency order and logs each to
`reproduce_paper.log`: differential expression → evolutionary backbones (Ka/Ks, dN/dS) →
co-expression conservation categories → promoter TF/TE scans → integration → enrichment and
GO → integrative model → all figures and supplementary tables. Set `STOP_ON_FAIL=1` to abort
on the first failing stage. Outputs land in `results/integration/`, `results/final_figures/`
and `manuscript/supplementary/`. Read the script top-to-bottom for the full ordered stage
list; it is the authoritative description of the pipeline.

## Pipeline architecture

The analysis is deliberately organised as many small, single-purpose scripts rather than a few
large ones. Each script produces one well-defined artefact — a figure, a table, or a named
intermediate — so every reported number traces to exactly one producer, and `reproduce_paper.sh`
runs, times and logs each step independently (a reviewer can re-run any single stage in isolation
and see where a value comes from). This structure favours **reproducibility and traceability** over
authoring brevity: the file count is higher than a working analysis script would need, but the
provenance of every figure and number is unambiguous.

Run in dependency order by the driver, the scripts group into these stages:

1. **Differential expression** (`src/BioQA_DE/`) — DESeq2 per stress/tissue condition and DEG-overlap
   counts; feeds Figures 1–2 and the mechanism analyses.
2. **Co-expression network** (`ComPlEx.R`, `ComPlExDataPrep.R`, `cliques_step1/1b/2.R`) — the ComPlEx
   co-expressolog network and conservation categories (the deposited network output is the default
   starting point).
3. **Evolutionary rates** (`kaks_within_species_sd.py`, `cross_species_ks.py`, `kaks_yn00.py`,
   `run_cross_species_dnds.sh`, `single_copy_dnds_breadth.py`) — within- and cross-species Ka/Ks and
   dN/dS backbones.
4. **Promoter TF/TE** (`extract_upstream_seqs.py`, `pa_ps_promoter_te_presence.py`,
   `te_promoter_family_analysis.py`, `chs3_promoter_motifs.py`, `run_tfdb_prediction.py`) — upstream
   sequence extraction, TE presence, and FIMO TF-motif scans.
5. **Integration** (`integration_analysis.R`, `integrative_conservation_model.R`,
   `build_category_universe.py`, `build_network_degree.py`) — assembles the 1:1-ortholog backbone and
   the integrative conservation model (Supplementary Figure S5).
6. **Enrichment, selection and population genomics** (`enrichment_tests_extended.R`,
   `tf_enrichment_by_category.py`, `stress_selection_enrichment.R`, `pnps_confound_analysis.py`,
   `threshold_sensitivity.py`, `wood_clique_and_conditioned_pav.py`, `gwas_deg_overlap.R`).
7. **GO enrichment and conserved dynamics** (`coex_category_go.R`, `deg_directional_go.R`,
   `subset_go.R`, `conserved_coexpression_dynamics.R`; all GO via the single `src/lib/go_enrichment.R`).
8. **Figures and tables** (`src/figures/`, `src/tables/`) — one producer per artefact, composited by
   `assemble_figures.R`.

Because every output is regenerated from the deposited inputs, `results/` and
`manuscript/supplementary/*.xlsx` are not stored in this repository (see *Reproducing the analysis*).

### GO enrichment (single shared method)

Every GO analysis calls `src/lib/go_enrichment.R`, so the method is identical throughout:

- topGO `weight01` algorithm with Fisher's exact test. Because `weight01` conditions each
  term on its neighbours in the GO DAG, the reported *p*-values are already adjusted for the
  dependency structure of the ontology; no additional Benjamini–Hochberg step is applied
  (per the topGO authors' guidance).
- `nodeSize = 5` (terms with fewer than five annotated background genes are dropped).
- All three ontologies (BP, MF, CC) are computed and written to the supplementary tables;
  main-text tables show BP only.
- gene→GO from eggNOG-mapper + InterPro, one consistent annotation per species used identically by
  every GO analysis, both under `data/annotation/`: *Picea abies* from
  `data/annotation/gene_annotation.tsv.gz`, *Pinus sylvestris* from
  `data/annotation/pine_GO_annotation.tsv.gz`. Both are the same eggNOG+InterPro table format
  (columns `id`, `eggnog_go`, `interpro_go`), parsed by the shared `build_gene2go()` in
  `src/lib/go_enrichment.R`.
- Each term carries a `plant_consistent` flag (term present in the Arabidopsis GO set,
  `org.At.tair.db`); main-text tables are filtered to plant-consistent BP terms at the
  presentation layer, while the supplementary tables retain the full term list plus the flag.
- Background = each analysis's expression universe intersected with the annotated genes.

### Software

The full toolchain is pinned in [`environment.yml`](environment.yml) — recreate it with:

```bash
mamba env create -f environment.yml   # or: conda env create -f environment.yml
conda activate conifer-repro
```

This installs everything the pipeline uses, so no tools need installing by hand:

- R ≥ 4.2 (developed on 4.6, arm64), Bioconductor (DESeq2, topGO, org.At.tair.db), CRAN
  (ggplot2, dplyr, tidyr, data.table, patchwork, openxlsx, ranger, MASS, gplots, brant, matrixStats)
- Python ≥ 3.11 with numpy, pandas, scipy, statsmodels, openpyxl; Biopython (Bio.codonalign, the
  cross-species dN/dS estimator — an *experimental* module, so its version is pinned; see `kaks_yn00.py`)
- PAML `yn00` (canonical Yang–Nielsen dN/dS), MAFFT, BLAST, and FIMO (MEME suite) for the promoter TF-motif scans
- PAML `codeml` and PRANK (codon-aware alignment) for the dN/dS robustness supplementary
  (`src/ComPlEx/dnds_robustness_subsample.py`; PRANK installed via a small dedicated env,
  e.g. `mamba create -n dnds_robust -c bioconda prank`, and pointed to via `PRANK_BIN`)
- The ComPlEx co-expression network build uses the companion Python port
  (https://github.com/natstreet/ComPlEx_python); point `COMPLEX_PY_REPO` at your checkout.

### Notes on two upstream layers

- **Raw reads → DESeq2 objects.** The DESeq2 dataset objects in the deposit are the starting
  point for differential expression; they were produced from raw RNA-seq with Trimmomatic,
  Salmon (against the *Picea abies* v2.0 and *Pinus sylvestris* v1.0 transcriptomes) and
  tximport/DESeq2, using the UPSC pipeline (https://github.com/UPSCb/UPSCb-common).
- **Co-expression network (ComPlEx).** `results/ComPlEx/` in the deposit is the network
  output. It was generated from the expression matrices by the ComPlEx algorithm
  (Python re-implementation: https://github.com/natstreet/ComPlEx_python; the R version is
  in `src/ComPlEx/ComPlEx.R` + `ComPlExDataPrep.R`), then processed by
  `src/ComPlEx/cliques_step1.R`, `cliques_step1b.R` and `cliques_step2.R`. `reproduce_paper.sh`
  starts from the deposited network output and runs `cliques_step2.R` onward; to rebuild the
  network from raw expression instead, run the ComPlEx and `cliques_step1*` scripts first.
- **Python vs R ComPlEx concordance.** The manuscript's statement that the Python
  re-implementation reproduces the published R implementation exactly (identical co-expressolog
  calls, Jaccard = 1.000 on the matched validation subset) is produced and recorded in the
  companion ComPlEx_python repository (https://github.com/natstreet/ComPlEx_python), under
  `validation/` — `validate_complex.R` (in-house R transcription) and
  `validate_against_canonical_rcomplex.R` (the canonical published `rcomplex`) versus
  `complex_py.py`, with the result written to `validation/VALIDATION_NOTE.md`.
